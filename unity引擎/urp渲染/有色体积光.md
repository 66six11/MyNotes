# 有色体积光学习文档

## 项目概述

本文档旨在总结在Unity URP渲染管线中实现有色体积光的技术细节和代码结构。通过分析项目中的Shader和C#脚本，我们将深入了解如何利用自定义级联阴影系统来实现体积光效果，并通过颜色信息进行调试和可视化。

## 核心实现分析

### 1. 自定义级联阴影系统

项目的核心是实现了一个自定义的级联阴影系统，该系统不仅生成标准的深度阴影贴图，还同时生成一个**颜色阴影贴图 (Color Shadow Map)**。这个颜色贴图的主要用途是可视化和调试，通过为每个级联分配不同的颜色，开发者可以直观地看到场景中哪些区域是由哪个级别的阴影贴图渲染的。

#### 1.1. CascadedShadowWithColorRGFeature.cs

这是一个 `ScriptableRendererFeature`，负责创建和执行自定义的渲染通道 (`Pass`)。它使用 Render Graph API 来管理渲染流程。

- **Settings类**: 允许开发者在Inspector中调整阴影质量、级联数量、图集分辨率、层级过滤等关键参数。
- **Pass类**: 继承自 `ScriptableRenderPass`，是整个系统的核心实现部分，负责计算主平行光的多个级联视图/投影矩阵，设置阴影图集和颜色图集的渲染目标，并将生成的阴影数据传递给着色器。

#### 1.2. GlassPass.shader

这是一个用于阴影投射的Shader，它定义了如何在阴影贴图中渲染对象。值得注意的是，它不仅渲染深度信息，还渲染颜色信息，这是实现颜色阴影贴图的关键。

#### 1.3. CustomCascadeShadow.hlsl

这是一个HLSL头文件，包含了在着色器中采样自定义级联阴影所需的所有函数和结构体定义。它实现了级联选择、坐标变换、深度比较和PCF软阴影。

### 2. 体积光实现原理

体积光，也称为丁达尔效应，是指光线穿过充满微粒的介质（如雾、烟）时，由于散射作用而变得可见的现象。在计算机图形学中，体积光通常通过光线步进（Ray-marching）技术来实现。

#### 2.1. 基于Ray-marching的体积光渲染

在实时渲染中，通常会采用光线步进（Ray-marching）的方式实现体积光的渲染。通过采样光路上的多个步进点，可以计算散射光线和正确的透光率积分。

#### 2.2. 实现步骤

1. **确定光线路径**: 从摄像机出发，确定观察射线的起点和终点。
2. **光线步进**: 沿着光线路径进行步进，采样每个点的光照信息。
3. **计算散射**: 根据介质的性质（如散射系数、吸收系数）和光照条件，计算每个采样点的散射光线。
4. **积分**: 将所有采样点的散射光线进行积分，得到最终的体积光效果。

### 3. 有色体积光实现

在本项目中，我们通过自定义级联阴影系统来实现体积光效果。具体来说，我们利用颜色阴影贴图来存储每个级联的颜色信息，并在着色器中进行采样和可视化。

#### 3.1. 阴影颜色信息

通过为每个级联分配不同的颜色，我们可以在着色器中根据采样点所在的级联来获取对应的颜色信息。这不仅可以用于调试，还可以作为体积光效果的一部分，例如，不同级联的体积光可以具有不同的颜色。

#### 3.2. 着色器实现

在 `test.shader` 中，我们通过 `SampleCustomShadow` 函数来采样自定义级联阴影，并获取阴影强度和颜色信息。然后，我们可以将这些信息用于计算最终的像素颜色，从而实现体积光效果。

```hlsl
CustomShadowData s = SampleCustomShadow(shadowCoord);
float3 debug = s.color;
return half4(debug, 1) * s.attenuation;
```

## 总结

通过分析项目代码，我们了解了如何在Unity URP渲染管线中实现一个自定义的级联阴影系统，并利用该系统来实现有色体积光效果。该系统不仅提供了标准的深度阴影贴图，还生成了颜色阴影贴图，用于调试和可视化。通过在着色器中采样这些信息，我们可以实现各种体积光效果，并根据需要进行调整和优化。
# 有色体积光学习文档（基于项目代码分析）

## 项目概述

本文档旨在总结在Unity URP渲染管线中实现**带颜色调试信息的自定义级联阴影**的技术细节和代码结构。虽然项目名称和请求提到了“体积光”，但通过对项目代码 (`Assets/RayMarching/`) 的分析，其核心实现是**一个自定义的级联阴影系统**。该系统除了生成标准的深度阴影贴图外，还生成一个**颜色阴影贴图 (Color Shadow Map)**，主要用于**可视化和调试**每个级联覆盖的区域。这与“有色体积光”中的“颜色”概念不同，这里的颜色是用于调试级联分布，而非模拟光线在介质中的散射颜色。

本文档将详细分析该项目代码，并探讨如何基于此系统进一步实现真正的“有色体积光”效果。

## 核心实现分析

### 1. 自定义级联阴影系统

项目的核心是一个自定义的级联阴影系统，位于 `Assets/RayMarching/RenderPass/GodLight.cs` 和 `Assets/RayMarching/Lib/CustomCascadeShadow.hlsl`。它旨在替代或补充URP内置的主光源级联阴影。

#### 1.1. `CascadedShadowWithColorRGFeature.cs` (ScriptableRendererFeature)

*   **功能**: 这是一个 `ScriptableRendererFeature`，负责创建和执行自定义的渲染通道 (`Pass`)。它使用现代的 Render Graph API 来管理渲染流程。
*   **`Settings`类**:
    *   `renderPassEvent`: 控制渲染通道在管线中的执行时机（默认为 `BeforeRenderingShadows`）。
    *   `layer`: 一个 `LayerMask`，用于指定哪些图层的对象参与阴影投射。这是对标准阴影系统的一个重要扩展。
    *   `overrideMaterial`: 可以指定一个替代材质用于阴影投射Pass。
    *   `colorGraphicsFormat`: 指定颜色阴影图集的格式。
    *   `cascadeDebugColors`: 一个颜色数组，用于为每个级联分配唯一的调试颜色。
*   **`Pass`类 (嵌套类)**:
    *   继承自 `ScriptableRenderPass`，是渲染逻辑的核心。
    *   在 `RecordRenderGraph` 方法中：
        1.  检查是否存在主光源且为方向光。
        2.  获取级联数量、图集大小、分割比例等参数。
        3.  **为每个级联计算视图矩阵 (`views`) 和投影矩阵 (`projs`)**。这是标准级联阴影的步骤。
        4.  **创建两个渲染图纹理 (TextureHandle)**:
            *   `depthTex`: 用于存储深度信息的阴影图集 (`_CustomMainLightShadowmapTexture`)。
            *   `colorTex`: 用于存储颜色信息的图集 (`_CustomMainLightShadowColorTexture`)。这是本项目的关键创新点之一。
        5.  **为阴影投射对象创建 `RendererListHandle`**: 使用 `k_ShadowCasterTag` (如 "UniversalForward", "SRPDefaultUnlit" 等) 来收集需要渲染到阴影贴图的对象。
        6.  **在 `SetRenderFunc` 的执行函数中**:
            *   遍历每个级联。
            *   设置当前级联的视口 (`SetViewport`) 和变换矩阵 (`SetViewProjectionMatrices`)。
            *   使用 `DrawRendererList` 将该级联对应的阴影投射对象渲染到 `depthTex` 和 `colorTex` 这两个附件上。
            *   渲染完成后，恢复摄像机的原始视图和投影矩阵及视口。
    *   **关键点**: 渲染到阴影图集时，同时写入深度和颜色附件。颜色附件的内容由用于阴影投射的Shader (`GlassPass.shader`) 决定。

#### 1.2. `GlassPass.shader` (阴影投射 Shader)

*   **功能**: 定义了对象如何渲染到阴影贴图中。
*   **ShadowCaster Pass**:
    *   顶点着色器 (`ShadowPassVertex`): 标准的将对象空间顶点转换到裁剪空间。
    *   片元着色器 (`ShadowPassFragment`):
        *   采样基础纹理 (`_BaseMap`)。
        *   **关键**: **直接返回采样到的颜色值** (`return color;`)。这使得渲染到颜色阴影图集 (`_CustomMainLightShadowColorTexture`) 的内容是对象纹理的颜色，而非统一的深度值。这为后续的调试和可视化提供了基础。
        *   注释掉的 `clip(color.a - _Cutoff);` 表明它也考虑了透明度Alpha测试。

#### 1.3. `CustomCascadeShadow.hlsl` (HLSL 库文件)

*   **功能**: 提供在着色器中采样自定义级联阴影所需的所有函数和结构体。
*   **纹理声明**:
    *   `TEXTURE2D_SHADOW(_CustomMainLightShadowmapTexture);`: 声明深度阴影图集纹理。
    *   `SAMPLER_CMP(sampler_CustomMainLightShadowmapTexture);`: 声明用于深度比较采样的采样器状态。
    *   `TEXTURE2D(_CustomMainLightShadowColorTexture);`: 声明颜色阴影图集纹理。
    *   `SAMPLER(sampler_CustomMainLightShadowColorTexture);`: 声明用于普通采样的采样器状态。
*   **`CustomShadowData` 结构体**:
    *   `attenuation`: 标准的阴影衰减因子 (0.0 到 1.0)。
    *   `color`: 从颜色阴影图集中采样到的颜色信息。
*   **`SampleCustomShadow` 函数**:
    *   接收世界空间坐标转换后的阴影坐标 (`shadowCoord`)。
    *   调用 `SampleShadowmap` 从深度阴影图集中获取标准的阴影衰减值 (`attenuation`)。
    *   使用 `SAMPLE_TEXTURE2D` 从颜色阴影图集中采样颜色值 (`color`)。
    *   返回包含 `attenuation` 和 `color` 的 `CustomShadowData` 结构。

#### 1.4. `test.shader` (调试/示例 Shader)

*   **功能**: 一个简单的着色器，用于展示如何使用 `CustomCascadeShadow.hlsl` 提供的功能。
*   **Forward Pass**:
    *   顶点着色器 (`vert`): 标准顶点处理。
    *   片元着色器 (`frag`):
        *   使用 `TransformWorldToShadowCoord` 将世界坐标转换为阴影坐标。
        *   调用 `SampleCustomShadow` 获取自定义阴影数据 (`s`)。
        *   **关键**: **直接显示采样到的颜色信息 (`s.color`) 与阴影衰减 (`s.attenuation`) 的乘积** (`return half4(debug, 1) * s.attenuation;`)。这使得被照亮且在不同级联中的区域会显示不同的调试颜色，清晰地可视化了级联的分布。

### 2. 与“体积光”的关系分析

该项目实现的**不是传统意义上的体积光 (Volumetric Lighting)**。体积光通常指：
1.  模拟光线在参与介质（如雾、烟、云）中的散射。
2.  通过光线步进 (Ray-marching) 在视线方向上积分光照和透射率。
3.  最终效果是看到“光束”本身，带有颜色、亮度衰减等。

本项目实现的是：
1.  一个**改进的、带颜色调试的级联阴影系统**。
2.  生成的“颜色”主要用于**调试级联分布**，而非模拟介质散射。
3.  `test.shader` 的输出是**物体表面**根据其所在阴影级联显示不同颜色，而不是在空气中渲染光束。

### 3. 如何基于此项目实现“有色体积光”

要在此基础上实现真正的“有色体积光”，可以考虑以下方向：

1.  **创建体积光渲染通道 (Volume Light Pass)**:
    *   创建一个新的 `ScriptableRendererFeature` 和 `ScriptableRenderPass`。
    *   该Pass需要在不透明和透明物体渲染之后执行。
2.  **光线步进 (Ray-marching)**:
    *   在全屏或全屏四边形 (Fullscreen Quad) 的Shader中实现光线步进。
    *   需要访问摄像机参数、深度纹理 (`_CameraDepthTexture`)、甚至法线纹理来确定光线路径。
3.  **光照积分**:
    *   在步进过程中，对每个采样点：
        a.  重建世界坐标。
        b.  使用本项目提供的 `SampleCustomShadow` 函数获取该点的阴影衰减 (`attenuation`)。
        c.  根据光源颜色、采样点到光源的距离和阴影衰减计算光照贡献。
        d.  应用透射率 (Transmittance) 模型，模拟光线在介质中的衰减。
        e.  可以考虑简单的相位函数 (Phase Function) 来模拟散射方向性。
4.  **颜色处理**:
    *   累积所有采样点的光照贡献，得到体积光的颜色和亮度。
    *   这个累积结果可以是单色的，也可以根据散射模型计算出RGB颜色，从而实现“有色”。
5.  **后期处理合成**:
    *   将计算出的体积光效果与场景颜色 (`_CameraOpaqueTexture` 或屏幕颜色) 进行混合。

# 有色体积光实现思路（基于项目分析）

## 1. 当前项目核心：带颜色的自定义级联阴影

项目的核心实现是一个改进的级联阴影系统，其主要特点和实现思路如下：

*   **双重渲染目标**：在渲染主光源的级联阴影时，系统不仅仅渲染深度信息到一张阴影图集（Shadow Atlas），同时还渲染颜色信息到另一张颜色图集（Color Atlas）。
*   **颜色来源**：渲染到颜色图集的内容并非统一的阴影值，而是由阴影投射物体的材质（在 `GlassPass.shader` 的 `ShadowPassFragment` 中）决定。具体来说，该Shader的阴影投射Pass直接输出了物体纹理的颜色。这意味着，不同颜色的物体在阴影颜色图上会留下不同的印记。
*   **级联标识**：虽然Shader本身输出的是物体颜色，但系统通过为每个级联分配一个独特的视口（Viewport）在图集中进行渲染。这间接地使得不同级联区域具有了不同的基础颜色（如果物体本身颜色不同）或可以通过后处理区分。
*   **调试与可视化**：最关键的部分在于 `test.shader`。它在渲染物体表面时，会查询自定义阴影系统。该系统返回两个值：标准的阴影衰减因子（`attenuation`）和从颜色图集中采样到的颜色（`color`）。`test.shader` 将这两个值相乘并输出，使得被光照到的区域会根据其所在的阴影级联显示出不同的颜色，从而实现了级联分布的可视化。

**总结**：项目实现了一个可以生成颜色信息的自定义阴影系统，其主要目的是**调试阴影级联的覆盖范围**，而不是模拟体积光。

## 2. 从阴影系统到有色体积光的实现思路

要基于当前项目实现真正的“有色体积光”，需要增加一个全新的渲染流程，其核心思路如下：

*   **创建独立的体积光渲染通道**：
    *   不再依赖物体表面的渲染，而是创建一个**屏幕后处理**或**全屏三角形/四边形**的渲染过程。
    *   这个过程通常在所有不透明和透明物体渲染完毕之后进行。

*   **光线步进 (Ray Marching)**：
    *   **确定步进路径**：对于屏幕上的每个像素，需要确定一条光线（从摄像机出发，穿过该像素）。
    *   **重建世界坐标**：结合摄像机参数和深度图 (`_CameraDepthTexture`)，可以计算出该像素对应的世界坐标。
    *   **确定步进范围**：确定光线在场景中的有效步进起点和终点。例如，可以是摄像机近裁面到远裁面，或者更优化地，是光线进入/离开一个体积光有效区域（如光锥）的点。
    *   **执行步进**：沿着这条光线，从起点到终点，按一定步长（Step Size）进行多次采样。

*   **光照与散射计算**：
    *   **采样点处理**：对于光线步进过程中的每一个采样点：
        a.  **重建世界坐标**：获取该点的精确世界坐标。
        b.  **阴影查询**：调用项目中已有的 `SampleCustomShadow` 函数，传入该点的世界坐标，获取该点是否在阴影中（即阴影衰减因子 `attenuation`）。这是判断光线能否到达该点的关键。
        c.  **光照计算**：如果该点不受阴影遮挡 (`attenuation` 接近 1)，则计算光源在该点的光照贡献。这通常包括光源颜色、距离衰减等。
        d.  **透射率 (Transmittance) 积分**：模拟光线从光源传播到该点，以及从该点传播到摄像机的过程中，因被介质吸收和散射而造成的能量损失。这通常是一个累积的计算过程。
        e.  **散射模型 (可选)**：应用相位函数（Phase Function）来模拟光线在该点向不同方向散射的比例，特别是向摄像机方向散射的部分。这是实现“有色”体积光的关键之一，因为不同波长的光散射特性可能不同（如瑞利散射对蓝光影响更大）。
        f.  **累积贡献**：将该点计算出的、向摄像机方向散射的光亮度累加起来。

*   **颜色与最终合成**：
    *   **体积光颜色**：经过对整条光线的步进和积分，最终得到的是该像素对应的体积光颜色和亮度。这个颜色可以是单色的，也可以是根据散射模型计算出的RGB值，从而体现出“有色”的特性。
    *   **与场景合成**：将计算出的体积光颜色与当前屏幕颜色（通常是 `_CameraOpaqueTexture`，即不透明物体渲染结果）进行混合（通常是加法混合或屏幕混合），得到最终带有体积光效果的画面。

## 3. 总结

项目的现有代码提供了一个强大的、可查询的自定义阴影系统，这是实现体积光的重要基础。通过查询阴影，我们可以知道光线是否被遮挡。

要实现“有色体积光”，核心思路是：
1.  **独立渲染通道**：创建一个后处理步骤。
2.  **光线步进**：在屏幕空间对每个像素发出的光线进行采样。
3.  **结合阴影**：在每个采样点利用项目已有的阴影系统判断光照遮挡。
4.  **物理模拟**：计算光线在介质中的散射和透射，应用相位函数等模型。
5.  **颜色积分**：累积所有采样点的贡献，形成体积光的颜色。
6.  **画面合成**：将体积光效果叠加到最终场景图像上。

这个过程与当前项目的阴影可视化功能是完全不同的渲染目标和技术路径。
